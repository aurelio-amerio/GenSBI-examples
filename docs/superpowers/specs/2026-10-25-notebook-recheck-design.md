# Example notebooks re-check — design

Date: 2026-10-25

## Intent

GenSBI has changed a lot over the past months, and the example notebooks in
this repo have not been re-checked against it. At least one typo is already
known (in `getting_started/my_first_model`). The goal is that **every notebook
in the repo runs end to end against the current GenSBI, with no code errors and
no typos in prose or comments**, and that each notebook is regenerated from its
proper source of truth.

## Goals

- Every `.ipynb` tracked in the repo (25 notebooks, listed below) runs top to
  bottom without errors against the current GenSBI.
- Typos fixed: prose, comments, code errors, stale API usage, wrong Colab
  links/paths. Also the top-level `README.md` (e.g. it says "CUDA 12" next to a
  `cuda13` install command) and per-example `README.md` files where they
  describe the notebook.
- Each fix lands in the notebook's **source of truth** (see below), and every
  notebook is regenerated from it at the end.
- Committed notebooks have **no outputs**. Figures are shown via linked static
  images (the existing, more resilient approach).

## Non-goals

- No retraining of models. Committed checkpoints are expected to keep working.
- No refactors, restructuring, or new content. Small fixes only.
- No changes to the GenSBI library code (`/home/aure/github/GenSBI`). If a
  notebook breaks because of a library bug, flag it, don't fix the library.
  The one exception is packaging: add `imageio` to the `examples` extra in
  GenSBI's `pyproject.toml` (see Decisions).
- No regeneration of the static images linked from notebooks/READMEs.
- Tracked `.py` files that are not notebook copies stay untouched: training
  scripts, `getting_started/first_model.py` (training script used by
  `sub/train_my_first_model.sub`), and `NDE/gensbi_dist.py` (helper module
  imported by `gensbi_text`).
- Tracked `.py` files that *are* stale py-percent copies of a notebook may be
  overwritten and are deleted at cleanup with the working copies. Currently
  this is only `methods_and_samplers/methods_and_samplers.py`.

## Anti-goals (would count as failure even if notebooks run)

- Fixes applied to a generated notebook but not to its template (they'd be
  lost on next regeneration).
- A template fix that repairs one task's notebook but breaks another task
  generated from the same template.
- Committed checkpoints overwritten, or outputs committed into notebooks.
- `.py` working copies left in the tree when merging to `main`.
- "Big" changes slipped in to make something run (e.g. changing model configs,
  retraining, rewriting sections).

## Decisions

- **gaussian_mixture joint tuning.** `gaussian_mixture/flow_flux1joint` was
  hand-tuned after generation (commit 825af76e: `use_ema=True` in
  `get_samples`, `range=((-9,-7),(4,6))` in `plot_marginals`). Make the template
  the real source by adding per-task placeholders for these to
  `notebook_template.md` and the replacement dicts in `make_notebook.py`, with
  defaults that reproduce the current output for every other task (other 14
  template notebooks currently regenerate identically, and must keep doing so).
- **NDE notebooks with committed outputs.** Strip outputs like every other
  notebook. Where a stripped figure has an existing PNG on disk, link it from
  the markdown; where none exists (e.g. `gensbi_text` only has GIFs), losing the
  figure is acceptable. Running correctly matters more than keeping every figure.
- **`imageio`.** Needed by the two_moons template (6 notebooks) and
  `NDE/gensbi_text`; not installed in the venv and not in `gensbi[examples]`.
  Add `imageio` to the `examples` optional-dependency group in
  `/home/aure/github/GenSBI/pyproject.toml` (a one-line change, committed
  directly on GenSBI's `main`), and
  install it into `/home/aure/github/GenSBI/.venv`. No change to the notebooks'
  `!uv pip install` lines for this.
- **`NDE/flow_matching_2d_unconditional_flux1joint`** currently trains by
  default (`restore_model = False`, `train_model = True`). Flip it to restore
  by default, like the other NDE notebooks; the committed checkpoint should
  work.

## Workflow (as decided)

1. **Branch.** All work happens on a dedicated branch off `main`.
2. **Make `.py` working copies.** For every notebook, create a jupytext
   py-percent copy next to it (for template notebooks: a copy of the *rendered*
   notebook for each task). These `.py` copies live on the branch only and are
   named `<notebook>.wip.py`, so they never collide with tracked `.py` files.
3. **Run the `.py`, not the notebook.** Execute each `.py` with
   `/home/aure/github/GenSBI/.venv/bin/python` on the GPU, **one at a time**
   (never two GPU jobs concurrently). Use a non-interactive matplotlib backend
   (`MPLBACKEND=Agg`). Notebook-only lines (`!uv pip install`, `!git clone`,
   `%cd`, `%load_ext autoreload`, etc.) are commented out by jupytext in the
   `.py`; they are not exercised but must still be checked for typos.
   Run from the notebook's own directory so relative checkpoint/config paths
   resolve. Some notebooks `savefig` over tracked PNGs; restore those files
   (`git checkout`) after each run so linked images don't change.
4. **Fix in the `.py`** until it runs clean and reads correctly.
5. **Port fixes back to the source of truth.** For template notebooks, collect
   fixes across all tasks sharing a template first, then edit the template
   once, making sure each fix is valid for every task it renders into.
6. **Regenerate all notebooks** from their sources, outputs stripped.
7. **Verify regeneration.** For each notebook, convert the regenerated
   `.ipynb` back to py-percent and diff its code against the `.py` that ran
   clean; they must match (modulo jupytext metadata/formatting). No full
   notebook execution, except **spot-check runs** of a few regenerated
   notebooks: at least one generic-template, one two_moons-template,
   `my_first_model`, and one `.ipynb`-only (e.g. an NDE notebook).
8. **Delete the `*.wip.py` working copies and the stale notebook copy
   `methods_and_samplers/methods_and_samplers.py`** (nothing else), then the branch is ready to merge.

## Checkpoints and results

- Notebooks restore committed checkpoints by default. These **should keep
  working**. If one fails to load, investigate why (e.g. renamed config key,
  changed default) and fix it if the fix is small and on the notebook side.
- If the cause is not a small notebook-side fix, **skip that example**: leave
  it as is, record it with the error and the suspected cause, and move on. It
  will be dealt with later.
- If a notebook runs but results look **badly off** (implausible posterior
  plots, C2ST far from the value in that example's `README.md`, broken
  diagnostics), flag it. Not expected, but keep an eye on it.

## Environment notes

  jupytext 1.19.1). `gensbi_examples` (this repo's `src/`) is not installed there; the

  need network access.

## Deliverables

- Branch with fixed templates / `.md` sources / `.ipynb`-only notebooks,
  regenerated notebooks (no outputs), README typo fixes, `.py` copies removed.
- A short report: per notebook, ran clean / fixed (what) / skipped (why), plus
  any flagged results.
